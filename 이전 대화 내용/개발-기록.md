## 2. 관리자 로그인/편집 기능 → Next.js 이전 (핵심 전환)

기존에 만든 "빌드 가이드"(`C:\Users\gile\Desktop\claude\가이드 에이전트\빌드 가이드`)와
**동일한 방식**으로 관리자 로그인 → 편집 → DB 저장 기능을 넣기로 결정.

> 정적 GitHub Pages로는 "서버 로그인 + DB 저장 + 모든 방문자 공유"가 불가능 →
> **Vercel + Neon Postgres + 쿠키 인증** 구조의 Next.js 앱으로 이전.

정적 원본은 `_legacy-static/`에 백업.

### 기술 스택 / 구조
- **Next.js 14 (App Router)** — 기존 포트폴리오 디자인은 `globals.css`로 그대로 이전.
- **인증**: `ADMIN_PASSWORD` 환경변수 → 로그인 시 `SHA256(비밀번호)`를 **HttpOnly 쿠키**로 발급,
  서버에서 timing-safe 비교 (`lib/admin-auth.ts`, 쿠키명 `portfolio_admin`).
- **저장소**: Neon Postgres `content_blocks`(key/value) 테이블.
  DB에 값이 없으면 컴포넌트의 fallback(기본 텍스트) 사용.

### 주요 파일

## 5. 배포 (Vercel)

1. Git 저장소 초기화 → GitHub(`PHG7819/GilePortfolio`)에 push.
2. Vercel 프로젝트 import → **Next.js** 자동 인식.
3. **Storage → Neon(Postgres) 연결**: 환경변수 자동 주입.
   - 주의: Neon 통합이 프리픽스 `DATABASE`를 붙여 `DATABASE_DATABASE_URL` 등으로 생성됨 →
     코드에서 여러 후보 이름을 자동 탐색하도록 `resolveDatabaseUrl()` 구현.
4. **Storage → Blob 연결**: `BLOB_READ_WRITE_TOKEN` 자동 주입(이미지 업로드용, "read-write token" 체크 필수).
5. **Environment Variables**에 `ADMIN_PASSWORD` 추가.
6. Neon SQL Editor에서 테이블 생성:
   ```sql
   CREATE TABLE IF NOT EXISTS content_blocks (
     key varchar(128) PRIMARY KEY,
     value text NOT NULL,
     updated_at timestamptz NOT NULL DEFAULT now()
   );
   ```
7. 프로젝트 이름을 `gile-devlog`로 변경 + Domains에 `gile-devlog.vercel.app` 추가.
   - 참고: `https://gile.devlog`는 실재하지 않는 TLD라 불가. 실제 짧은 주소가 필요하면 도메인 구매 후 연결.

## 6. 막판 디버깅: "추가/삭제가 화면에 반영 안 됨" (중요 교훈)

증상: 카드 삭제/추가를 눌러도 화면에 반영되지 않음. 여러 차례 원인을 좁혀가며 해결.

진단 과정(읽기 전용 진단 API/디버그 기록을 임시로 추가해 외부에서 DB 상태 직접 확인):

1. **로그인 창 잘림** — 헤더의 `backdrop-filter`가 fixed 기준 박스가 되어 로그인 모달이 헤더(64px) 안에 갇힘 → `createPortal(document.body)`로 해결.
2. **`window.confirm()` 차단** — 삭제 확인창이 반복되자 브라우저가 차단 → `confirm` 제거, **2단계 클릭 버튼**으로 대체.
3. **2단계 버튼의 `onMouseLeave` 해제** — 마우스 이동 시 armed 풀림 → 타이머 방식으로 변경.
4. **페이지/서버 순서 파싱 불일치** — 페이지는 `map(String)`, 서버는 `every(string)` 체크로 서로 다르게 해석 → 양쪽을 동일 로직(문자열 강제 변환 + null/빈 값 제거)으로 통일.
5. **(결정타) 페이지 데이터 캐싱** — `export const dynamic="force-dynamic"`만으론 부족했고, Next가 페이지의 DB 읽기 결과를 캐시해 추가/삭제 후에도 옛 목록을 보여줌 →
   **`unstable_noStore()`**를 페이지에 추가해 항상 최신 DB를 읽도록 수정.
6. 추가/삭제/저장의 화면 갱신을 `router.refresh()` 대신 **확실한 전체 새로고침(`window.location.reload()`)**으로 통일.
7. 진단용 코드(공개 GET / 디버그 기록 / DB 호스트 노출)는 원인 확정 후 **모두 제거**.

> 교훈: App Router에서 DB를 직접 읽는 동적 페이지는 `force-dynamic`만으로 안심하지 말고,
> 데이터가 매 요청 최신이어야 하면 `unstable_noStore()`(또는 적절한 캐시 무효화)를 명시할 것.
> 또한 클라이언트가 보내는 id와 서버 상태의 일관성(파싱 동일화)이 중요.

## 8. 운영·배포 편의 + KRAFTON 리브랜딩 (2026-07-08 세션)

### 8-0. DB 임시 키 정리
- `_debug.lastdelete` 등 진단용 키를 기록하던 코드는 커밋 `9953064`에서 이미 제거됨(코드상 잔재 없음).
- 다만 과거에 DB에 써진 행(row)은 남아있을 수 있어 Neon **SQL Editor**에서 직접 정리:
  ```sql
  DELETE FROM content_blocks
  WHERE key LIKE '\_debug.%' ESCAPE '\'
     OR key LIKE 'debug.%'
     OR key = '_debug.lastdelete';
  ```
  - `_`는 SQL 와일드카드라 `ESCAPE '\'`로 escape. 정상 키(`content:*`, `*.order`)는 안 걸림.
  - 로컬 `.env.local`의 `DATABASE_URL`이 비어 있어 클라이언트에서 직접 접속 불가 → Neon 콘솔에서 실행.

### 8-1. git push 자동화 — `git-push.bat`
- 매번 PowerShell을 열지 않도록 프로젝트 루트에 배치파일 생성. **더블클릭 → 자동 `add→commit→push`**.
- 커밋 메시지는 `auto update <날짜> <시간>` 자동 생성, 성공 시 3초 후 자동 종료(실패 시에만 창 유지).
- **중요 교훈(인코딩)**: 처음엔 한글 주석/메시지를 넣었더니 cmd가 .bat을 시스템 코드페이지(CP949)로 읽어 **깨지고 명령 해석까지 실패**함
  (`'ho'은(는) 내부 또는 외부 명령...` 류 에러). → **배치파일 내용을 전부 영문(ASCII)로** 작성해 해결.
- 참고: Git Bash에서 테스트 시 끝에 `timeout: invalid time interval '/t'`가 뜨는 건 MSYS의 `timeout`이 잡혀서일 뿐,
  실제 **탐색기 더블클릭(cmd.exe)** 에서는 정상 동작.

    - `fonttools`로 글리프 검증: A–Z·a–z·숫자·기호 포함(105 glyph) → 라벨 깨짐 없음 확인.
  - **Pretendard**(공식 한글+영문 본문) → 기존 Paperlogy 대체. `layout.tsx`에 jsDelivr CDN 링크(dynamic-subset) 추가.
- 규격 준수: 로고 자체 색/그라디언트 변형 없음, 헤더엔 가로형 로고.
- 소스 원본 폴더 `폰트와 로고/`는 대용량 PDF 포함이라 `.gitignore` 처리(실사용 폰트는 `public/fonts`에 복사됨).
  - 커밋 시 이전 폴더명 `이미지와 브랜드 로고/`가 `폰트와 로고/`로 이름 변경되며 옛 소스 중복본이 삭제로 잡힘 — 런타임 자산(`public/*`)은 별개라 무영향.

### 8-4. 피드백 반영(연속 미세 조정)
1. **오렌지 버튼 위 라벨 광택 가독성** — 버튼(오렌지)에 오렌지 글자 광택이 묻힘 → **버튼 라벨 한정 흰/은색 반짝임**으로 override
   (`.button:hover .btn-label` background-image = 흰↔은 그라디언트). 어두운 배경의 오렌지 광택·밝은 회색 버튼은 그대로.
2. **폰트 이질감(중요)** — KRAFTON Headline은 영문 대문자 전용이라 **한글 섞인 요소**(h1/h2·버튼·푸터 링크·이름)에 쓰면
   한글만 폴백돼 따로 놈 → 원칙 정립:
   - **KRAFTON Headline = 한글 안 섞이는 영문 라벨만**(섹션 kicker·상단/좌측 내비·푸터 칼럼 제목).
   - **Pretendard = 한글 포함/버튼/큰 제목/본문 전부.**
   - 푸터도 처음엔 제목/링크에 KRAFTON을 넣었다가(요청) 한글 링크(포트폴리오/경력기술서) 때문에 다시 링크/이름은 Pretendard로 환원.
3. **오른쪽 스크롤바 표시** — 기존에 `scrollbar-width:none`+`::-webkit-scrollbar{display:none}`로 숨겨져 있던 걸 해제.
   얇게(12px), 트랙 `#0a0a0b`, thumb 회색 → **hover 시 오렌지**. Firefox `scrollbar-color`도 대응.
4. **Tools 밴드 위치 이동** — About↔Skills 사이 독립 밴드였는데 About이 길어(min-height 80vh) 간격이 커서
   내비로 About 클릭/스크롤 시 Skills로 넘어가며 지나침 → **Tools를 Skills 섹션 안(스킬 박스 아래)로 이동**(`page.tsx`).
   Skills를 볼 때 스킬 카드 + Tools가 한 화면에 함께 보이도록.
5. **Tools 박스 제거** — 라이트 섹션 안에서 차콜 박스가 튐 → 배경/라운드 제거하고 **라이트 배경 위에 내용만 나열**.
   글자·원형 아이콘을 다크로 전환, `TOOLS` 라벨은 오렌지(kicker 톤), 위쪽 얇은 구분선만.
6. **내비 active 광택 지속** — 활성 섹션이 흰 글자로 라이트 배경에 묻힘 →
   **선택된 동안 hover와 동일한 오렌지 광택 애니메이션을 계속 출력**.
   - 왼쪽 네비: `.side-nav a.is-active .side-nav-label` 추가.
   - 상단 헤더 내비: `.nav-links a.is-active` 추가.

### 8-5. 이번 세션 커밋 흐름(요약)
- `pre-krafton`(태그)/`backup/pre-krafton`(브랜치) = 리브랜딩 이전 롤백 지점.
