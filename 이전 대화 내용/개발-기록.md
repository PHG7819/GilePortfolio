## 2. 관리자 로그인/편집 기능 → Next.js 이전 (핵심 전환)

기존에 만든 "빌드 가이드"(`C:\Users\gile\Desktop\claude\가이드 에이전트\빌드 가이드`)와
**동일한 방식**으로 관리자 로그인 → 편집 → DB 저장 기능을 넣기로 결정.

> 정적 GitHub Pages로는 "서버 로그인 + DB 저장 + 모든 방문자 공유"가 불가능 →
> **Vercel + Neon Postgres + 쿠키 인증** 구조의 Next.js 앱으로 이전.

정적 원본은 `_legacy-static/`에 백업.

### 기술 스택 / 구조
- **Next.js 14 (App Router)** — 기존 포트폴리오 디자인은 `globals.css`로 그대로 이전.
- **인증**: `ADMIN_PASSWORD` 환경변수 → 로그인 시 `SHA256(비밀번호)`를 **HttpOnly 쿠키**로 발급,
  서버에서 timing-safe 비교 (`lib/admin-auth.ts`, 쿠키명 `portfolio_admin`).
- **저장소**: Neon Postgres `content_blocks`(key/value) 테이블.
  DB에 값이 없으면 컴포넌트의 fallback(기본 텍스트) 사용.

### 주요 파일
```
app/
  layout.tsx              루트 레이아웃 + AdminProvider + 폰트/메타/파비콘

  api/list                POST 리스트(카드/항목) 추가·삭제
  api/upload              POST 이미지 업로드(Vercel Blob)
components/
```

### 편집 UX
- 헤더 우측 **관리자** → 로그인 → **편집** → 텍스트가 입력칸으로 → **저장**(DB 반영 → 새로고침).
- 모든 편집 텍스트는 `content:<key>`로 저장(`EditableText`).

## 3. 편집 기능 확장

### 3-1. 이미지 업로드 편집
- **Vercel Blob** 사용. 편집모드에서 이미지(초록 점선) 클릭 → 파일 선택 → `/api/upload`(관리자 전용) → 공개 URL 반환 → `content_blocks`에 저장.
- 대상: 프로젝트 콜라주/역량 아이콘/Learning/포트레이트/경력 이미지/Notion 카드/소셜 아이콘.
- `<a>`/카드 안 클릭 시 이동·모달 방지 가드 추가.

### 3-2. 항목 추가·삭제 (범용 리스트)
- `/api/list`로 일반화. `<list>.order`(JSON 배열) 키에 순서 저장, 각 항목은 `<prefix>.<id>.*` 키.
- 적용 리스트: `demo.cards`, `projects.feats`, `learning.cards`, `skills.cards`, `career.minis`, `career.entries`.
- `AddItemButton`/`DeleteItemButton`(2단계 클릭: "정말 삭제?" → 한 번 더).

## 5. 배포 (Vercel)

1. Git 저장소 초기화 → GitHub(`PHG7819/GilePortfolio`)에 push.
2. Vercel 프로젝트 import → **Next.js** 자동 인식.
3. **Storage → Neon(Postgres) 연결**: 환경변수 자동 주입.
   - 주의: Neon 통합이 프리픽스 `DATABASE`를 붙여 `DATABASE_DATABASE_URL` 등으로 생성됨 →
     코드에서 여러 후보 이름을 자동 탐색하도록 `resolveDatabaseUrl()` 구현.
4. **Storage → Blob 연결**: `BLOB_READ_WRITE_TOKEN` 자동 주입(이미지 업로드용, "read-write token" 체크 필수).
5. **Environment Variables**에 `ADMIN_PASSWORD` 추가.
6. Neon SQL Editor에서 테이블 생성:
   ```sql
   CREATE TABLE IF NOT EXISTS content_blocks (
     key varchar(128) PRIMARY KEY,
     value text NOT NULL,
     updated_at timestamptz NOT NULL DEFAULT now()
   );
   ```
7. 프로젝트 이름을 `gile-devlog`로 변경 + Domains에 `gile-devlog.vercel.app` 추가.
   - 참고: `https://gile.devlog`는 실재하지 않는 TLD라 불가. 실제 짧은 주소가 필요하면 도메인 구매 후 연결.

## 6. 막판 디버깅: "추가/삭제가 화면에 반영 안 됨" (중요 교훈)

증상: 카드 삭제/추가를 눌러도 화면에 반영되지 않음. 여러 차례 원인을 좁혀가며 해결.

진단 과정(읽기 전용 진단 API/디버그 기록을 임시로 추가해 외부에서 DB 상태 직접 확인):

1. **로그인 창 잘림** — 헤더의 `backdrop-filter`가 fixed 기준 박스가 되어 로그인 모달이 헤더(64px) 안에 갇힘 → `createPortal(document.body)`로 해결.
2. **`window.confirm()` 차단** — 삭제 확인창이 반복되자 브라우저가 차단 → `confirm` 제거, **2단계 클릭 버튼**으로 대체.
3. **2단계 버튼의 `onMouseLeave` 해제** — 마우스 이동 시 armed 풀림 → 타이머 방식으로 변경.
4. **페이지/서버 순서 파싱 불일치** — 페이지는 `map(String)`, 서버는 `every(string)` 체크로 서로 다르게 해석 → 양쪽을 동일 로직(문자열 강제 변환 + null/빈 값 제거)으로 통일.
5. **(결정타) 페이지 데이터 캐싱** — `export const dynamic="force-dynamic"`만으론 부족했고, Next가 페이지의 DB 읽기 결과를 캐시해 추가/삭제 후에도 옛 목록을 보여줌 →
   **`unstable_noStore()`**를 페이지에 추가해 항상 최신 DB를 읽도록 수정.
6. 추가/삭제/저장의 화면 갱신을 `router.refresh()` 대신 **확실한 전체 새로고침(`window.location.reload()`)**으로 통일.
7. 진단용 코드(공개 GET / 디버그 기록 / DB 호스트 노출)는 원인 확정 후 **모두 제거**.

> 교훈: App Router에서 DB를 직접 읽는 동적 페이지는 `force-dynamic`만으로 안심하지 말고,
> 데이터가 매 요청 최신이어야 하면 `unstable_noStore()`(또는 적절한 캐시 무효화)를 명시할 것.
> 또한 클라이언트가 보내는 id와 서버 상태의 일관성(파싱 동일화)이 중요.

## 7. 현재 상태 / 운영 메모

- 편집 가능 범위: 거의 모든 텍스트 + 주요 이미지 + 6개 섹션의 항목 추가/삭제.
- 환경변수(.env.local 또는 Vercel): `DATABASE_URL`(또는 Neon 프리픽스 변형), `ADMIN_PASSWORD`, `BLOB_READ_WRITE_TOKEN`.
- 방문자 카운터 `SITE_KEY`는 `components/PortfolioClient.tsx`에서 본인 고유값으로 관리.
- 로컬 실행: `npm install` → `.env.local` 설정 → `npm run db:push`(또는 위 SQL) → `npm run dev`.
- 배포 갱신: `git push` → Vercel 자동 재배포. 환경변수 변경 시 Redeploy 필요.
